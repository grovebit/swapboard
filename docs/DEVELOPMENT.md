# Developing ClipSync

This page is for people who want to build ClipSync themselves or change it. To *use* ClipSync, see the [README](../README.md).

## Architecture

```
Alfred workflow ──► clipsync CLI ──unix socket──► clipsync agent (LaunchAgent) ◄══ WebSocket over Tailscale, AES-GCM ══► Android app
```

| Part | Where | What it is |
|---|---|---|
| Mac agent + CLI | `mac/` | Swift package with no third-party dependencies. It builds one binary, `clipsync`, which is both the CLI and the background agent. `ClipSyncCore` holds the protocol, crypto, sessions and config; it's unit-tested. |
| Alfred workflow | `workflow/` | `info.plist` and shell scripts that call `./clipsync`. Gives the `clip` keyword, hotkey, Universal Action, notifications (External Trigger `notify`) and User Configuration. |
| Android app | `android/` | Kotlin + Compose. Contains: <ul><li>a foreground service (type `connectedDevice`)</li><li>the Quick Settings tile and share / text-selection targets</li><li>pairing (ML Kit code scanner or a pasted link)</li><li>the optional Shizuku clipboard watcher</li></ul> |
| Protocol | `protocol/` | [`PROTOCOL.md`](../protocol/PROTOCOL.md) is the wire spec. `vectors.json` holds test vectors that both test suites must pass. |

### Mac

- **Agent lifecycle.** `clipsync start` does three things:
  1. copies the binary to `<data>/bin/clipsync`, so the agent doesn't depend on where the workflow lives;
  2. writes `~/Library/LaunchAgents/com.clipsync.agent.plist` (`RunAtLoad`, `KeepAlive`);
  3. bootstraps it with `launchctl`.

  `clipsync stop` boots it out and removes the plist.
- **Data directory.** `$alfred_workflow_data` (set by Alfred), else `CLIPSYNC_DATA_DIR`. It falls back to `~/Library/Application Support/Alfred/Workflow Data/com.clipsync.alfred/`, including when Alfred isn't installed. It contains:
  - `config.json` (mode 0600): pairings and settings
  - `agent.log`
  - `agent.sock`: the control channel between the CLI and the agent
  - `pair-qr.png`, while a pairing is in progress
  - `bin/clipsync`
- **Settings.** Alfred passes User Configuration values only to the scripts it runs, never to the LaunchAgent. So every CLI call copies changed values into `config.json` and sends `reload` to the agent.
  - Without Alfred, the keys in `config.json` → `settings` are `port`, `paused`, `notifyOnReceive`, `maxClipKB` and `ignoredApps`.
  - Restart the agent after editing them by hand.
- **Clipboard.** The agent polls `NSPasteboard.changeCount`.
  - It skips items carrying the [nspasteboard.org](http://nspasteboard.org) `Concealed`, `Transient` or `AutoGenerated` markers.
  - It skips copies made while an ignored app is frontmost.
  - It skips its own writes, which it tags with `com.clipsync.remote`.
  - Received sensitive clips are written with `org.nspasteboard.ConcealedType`.
- **Notifications** go through the workflow's External Trigger when Alfred is installed, otherwise through `display notification`.

### Android

- minSdk 29 (Android 10), target and compile SDK 37. Newer APIs are behind version checks, and `./gradlew lint` must report no `NewApi` errors.
- The pairing key is wrapped with an Android Keystore AES-GCM key. App backups are disabled.
- **Automatic phone → Mac.** Android 10+ only lets the foreground app read the clipboard, but the shell user (uid 2000) holds `READ_CLIPBOARD_IN_BACKGROUND`. `shizuku/ClipWatcherService` runs as a Shizuku *user service* under that uid:
  - it registers a clipboard listener on the hidden `IClipboard` service, falling back to polling;
  - it hands new text to the app over AIDL;
  - the app filters what it receives with `clip/AutoSendFilter`.

### Tailscale only (keep it that way)

ClipSync deliberately never talks over the LAN.
- **Mac:** the listener binds to the Mac's Tailscale IPv4 (100.64.0.0/10) through `requiredLocalEndpoint`.
  - It rejects peers outside that range.
  - It rejects connections that arrive on a Wi-Fi, Ethernet or cellular interface.
  - When Tailscale comes up or its address changes, it re-binds.
- **Android:**
  - `TailnetPolicy` drops every pairing host that isn't a Tailscale address.
  - `TailscaleNetwork` binds the socket to the VPN network whose routes cover the host.
  - Without that VPN, the app doesn't connect at all.
  - The app doesn't hold `ACCESS_LOCAL_NETWORK`.

Please don't add a LAN, mDNS or Wi-Fi fallback.

## Requirements

- macOS with Xcode or the Xcode command-line tools (Swift 6)
- Android Studio, with Android SDK platform 37
  - The project uses AGP 9.2.1 and the Gradle 9.5.0 wrapper.
  - `make` runs Gradle with Android Studio's bundled JDK when it finds one.
- Node.js 18 or newer, only to regenerate the protocol test vectors

## Make targets

| Command | What it does |
|---|---|
| `make test` | Swift and Kotlin unit tests. Both run `protocol/vectors.json`. |
| `make test-mac` / `make test-android` | One side only. |
| `make mac` | Builds a universal (arm64 + x86_64) release binary for macOS 12+. It copies it to `workflow/clipsync` and signs it (see below). |
| `make dev-install` | `make mac`, then symlinks `workflow/` into Alfred, so edits take effect immediately. |
| `make dev-uninstall` | Removes that symlink. |
| `make package` | Builds `dist/ClipSync.alfredworkflow`. |
| `make android` | Builds the debug APK at `android/app/build/outputs/apk/debug/app-debug.apk`. |
| `make install-android` | Installs the debug APK on the phone connected over adb. |
| `make vectors` | Regenerates `protocol/vectors.json` with Node's crypto, which serves as an independent reference implementation. |
| `make clean` | Removes build outputs. |

### Code signing

By default, `make mac` signs ad hoc (`SIGN_ID=-`). An ad-hoc signature changes on every build, so macOS may ask its permission questions again after a rebuild. To avoid that, sign with a stable identity:

```sh
make mac SIGN_ID="Apple Development: Your Name (TEAMID)"
```

## Testing the Mac side without a phone

`clipsync debug-client` acts as a fake phone. To keep the test away from your real setup, use a separate data directory and port:

```sh
export CLIPSYNC_DATA_DIR=/tmp/clipsync-test
mkdir -p $CLIPSYNC_DATA_DIR && echo '{"settings":{"port":48699}}' > $CLIPSYNC_DATA_DIR/config.json
clipsync agent &                         # agent in the foreground of this shell
clipsync pair --no-show                  # creates a pairing without showing the QR code
clipsync debug-client --exit-after 10    # prints the clips the Mac sends
clipsync debug-client --send "hello"     # sends a clip to the Mac
clipsync debug-client --wrong-key        # expect: closed code=4001
```

The agent still listens only on the Mac's Tailscale address, so Tailscale must be connected.

## Ground rules

- Never log clipboard text. Log sizes and device names only.
- Keep automatic phone → Mac off by default.
- Any protocol change must update `PROTOCOL.md`, the vector generator and both test suites, together.
